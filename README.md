# Unfurl

Unfurl is a small native Windows 11 archive workspace. It follows the useful part of Unfold's product: one calm drop surface for previewing archives, extracting them, and compressing files. Its interaction model is rebuilt around WinUI 3, Segoe UI Variable, Fluent controls, Mica, Explorer paths, and Windows-first deployment.

The repository keeps the archive engine independent from the UI. `unfurl_core` owns format detection, bounded preview, ZIP/7Z/TAR compression, ZIP password validation, split volumes, cancellation, path traversal checks, symlink checks, temporary staging, and no-overwrite commits. The WinUI target only schedules that work away from the UI thread and presents state.

ZIP supports AES or ZipCrypto passwords and split volumes. Split output uses `.zip.001`, `.zip.002`, and so on; selecting the first volume transparently joins the sequence for preview or extraction. 7Z output uses libarchive's native writer; passwords and split volumes are intentionally ZIP-only.

The implementation is deliberately conservative:

- Archive writes are staged in a private directory and renamed into place only after the writer closes successfully.
- Extracted paths reject absolute names, drive prefixes, `..`, oversized/deep names, unsafe symbolic links, and hard links.
- Existing files are never replaced automatically; a numbered Windows-style suffix is selected instead.
- Cancellation is checked while reading and writing. Failed or cancelled operations remove their staging tree.
- Preview reads headers only and caps the list at 250 entries. It never creates extracted output.
- The app does not poll or render continuously while idle. Progress is event-driven from the archive worker.

## Requirements

- Windows 11, Visual Studio 2026 Build Tools or newer with the Desktop C++ workload.
- CMake 3.28 or newer and Ninja.
- vcpkg at the pinned manifest baseline, with `VCPKG_ROOT` set.
- Windows App SDK **2.4.0** restored by `eng/restore-windows-app-sdk.ps1`.

Windows App SDK 2.4.0 is the current stable 2.4 package. C++/WinRT headers are generated by the Windows SDK that ships with Visual Studio; this avoids bringing a second copy of the projection into the application package.

## Build and test

```powershell
git clone https://github.com/your-org/Unfurl.git
cd Unfurl
$env:VCPKG_ROOT = 'C:\\src\\vcpkg'
./eng/restore-windows-app-sdk.ps1
cmake --preset core-tests
cmake --build --preset core-tests
ctest --preset core-tests
cmake --preset windows-release
cmake --build --preset windows-release
```

For a core-only build on a machine without MSVC, use any C++23 compiler supported by libarchive and configure with `-DUNFURL_BUILD_APP=OFF`.

The unpackaged development build accepts a dropped file path as its launch argument. `installer/UnfurlShell.reg` adds per-user Explorer commands for extract/compress; edit the installed executable path before importing it. `UninstallUnfurlShell.reg` removes those entries.

## Release shape

Release automation is intentionally small: build the Release preset, collect the executable and Windows App SDK runtime dependencies, sign the MSIX or unpackaged installer in the release environment, and publish a SHA-256 manifest. The CI workflow builds the core and WinUI targets separately so a missing UI SDK cannot hide a core regression.

## Upstream study

The product and engineering constraints were derived from [L0stInFades/Unfold](https://github.com/L0stInFades/Unfold): task-oriented compression/extraction, native drag and drop, bounded preview, cancellation-aware streaming, no-overwrite atomic publishing, strict path validation, and no idle GPU work. Unfurl keeps those constraints and changes the shell, typography, material, title-bar behavior, and Explorer integration to Windows 11 conventions.
