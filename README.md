# Unfurl

[简体中文说明](README.zh-CN.md)

The current UI edition is Simplified Chinese. Application-owned labels, status messages, picker titles, and errors are translated; original third-party diagnostics remain available in error tooltips.

Unfurl is a small native Windows 11 archive workspace. It follows the useful part of Unfold's product: one calm drop surface for previewing archives, extracting them, and compressing files. Its interaction model is rebuilt around WinUI 3, Segoe UI Variable, Fluent controls, Mica, Explorer paths, and Windows-first deployment.

The repository keeps the archive engine independent from the UI. `unfurl_core` owns format detection, bounded preview, ZIP/7Z/TAR compression, ZIP password validation, split volumes, cancellation, path traversal checks, symlink checks, temporary staging, and no-overwrite commits. The WinUI target only schedules that work away from the UI thread and presents state.

ZIP supports AES or ZipCrypto passwords and split volumes. Split output uses `.zip.001`, `.zip.002`, and so on; selecting the first volume transparently joins the sequence for preview or extraction. Dropping several archives runs extraction sequentially and keeps each result beside its source, while a multi-file drop is compressed as one archive. 7Z output uses libarchive's native writer; passwords and split volumes are intentionally ZIP-only.

The toolbar opens archives or adds files and folders through native Windows pickers. Compression exposes the archive name, format, optional ZIP password, volume size in MiB, and destination. Adding an existing archive through **Add files** compresses it as a source file. **Show output** selects the result in Explorer. Closing during an operation requests cancellation and waits for staging cleanup.

The interface follows the structure of Windows Settings: a native navigation pane switches between compression and extraction, a bounded content column contains a compact file table and aligned output rows, and password/split settings live under **Options**. **Appearance** at the bottom of the navigation pane offers System, Light, and Dark modes. Narrow windows collapse the navigation to an icon rail and rearrange the archive-name field; the operation bar stays visible while the content scrolls. Mica continues through the WinUI title bar and navigation pane, with translucent Fluent surfaces for content and native Acrylic for flyouts. The title bar hosts the navigation toggle while Windows retains its caption buttons, drag behavior, and Snap layouts. Caption buttons follow the selected theme without an accent-colored background. System materials provide their own fallback when transparency is unavailable. The app retains its embedded multi-resolution icon, PerMonitorV2 DPI awareness, and DPI-scaled window dimensions so WinUI renders text and controls at the display's scale.

The implementation is deliberately conservative:

- Archive writes are staged in a private directory and renamed into place only after the writer closes successfully.
- Extracted paths reject absolute names, drive prefixes, `..`, oversized/deep names, unsafe symbolic links, and hard links.
- Existing files are never replaced automatically; a numbered Windows-style suffix is selected instead.
- Cancellation is checked while reading and writing. The WinUI operation bar exposes a Cancel action, and failed or cancelled operations remove their staging tree.
- Preview reads headers only and caps the list at 250 entries. It never creates extracted output.
- The app does not poll or render continuously while idle. Progress is event-driven from the archive worker.

## Requirements

- Windows 11, Visual Studio 2026 Build Tools or newer with the Desktop C++ workload.
- CMake 3.28 or newer and Ninja.
- vcpkg at the pinned manifest baseline, with `VCPKG_ROOT` set.
- Windows App SDK **2.4.0** restored by `eng/restore-windows-app-sdk.ps1`.

Run the commands below from a Visual Studio Developer PowerShell so the MSVC and Windows SDK include/lib environment is loaded.

Windows App SDK 2.4.0 is the current stable 2.4 package. C++/WinRT headers are generated by the Windows SDK that ships with Visual Studio; this avoids bringing a second copy of the projection into the application package.

## Build and test

```powershell
git clone https://github.com/L0stInFades/Unfurl.git
cd Unfurl
$env:VCPKG_ROOT = 'C:\\src\\vcpkg'
./eng/restore-windows-app-sdk.ps1
cmake --preset core-tests
cmake --build --preset core-tests
ctest --preset core-tests
cmake --preset windows-release
cmake --build --preset windows-release
```

For a core-only build on a machine without MSVC, use any C++23 compiler supported by libarchive and configure with `-DUNFURL_BUILD_APP=OFF`.

The unpackaged build accepts one or more paths as launch arguments. `Unfurl.exe --compress "C:\Path\To\file.zip"` explicitly selects compression, including when the input is already an archive. For per-user Explorer integration, run `installer/install-shell.ps1 -Executable C:\Path\To\Unfurl.exe`; it registers extract commands for supported archive extensions and compress commands for files and folders. Run `installer/uninstall-shell.ps1` to remove them. These classic context-menu commands appear under **Show more options** on Windows 11. The `.reg` templates use `C:\Program Files\Unfurl\Unfurl.exe`; adjust that path before importing them.

### UI verification

Run the following in PowerShell 7 on an interactive Windows desktop after building. The verification script brings its own test windows to the foreground, exercises native pickers and compression/extraction, checks UTF-8 filenames and ZIP timestamps with .NET, verifies cancellation cleanup, and saves screenshots in `artifacts/ui-verification`. It closes its test windows when finished.

```powershell
./eng/verify-ui.ps1
./eng/capture-window.ps1 -Output artifacts/screenshots/unfurl.png
./eng/capture-window.ps1 -Width 560 -Height 480 -Output artifacts/screenshots/compact.png
```

The screenshot script accepts window dimensions in DIPs and reports the actual DPI and PerMonitorV2 status. Both scripts accept `-Executable` to check a packaged build. Core tests cover all output formats, passwords, split archives, Unicode paths, timestamps, collision handling, bounded preview, cancellation, and unsafe paths. See [verification notes](docs/verification.md) for the tested environment and remaining coverage limits.

## Release shape

Install the signed MSIX through [Unfurl.appinstaller](https://github.com/L0stInFades/Unfurl/releases/latest/download/Unfurl.appinstaller) to receive automatic updates from GitHub Releases. Windows checks at launch and every eight hours in the background. The initial release is self-signed and requires trusting the project's public certificate once. Follow the [installation and release guide](docs/updates.md) for certificate verification, installation, update behavior, and local signing with `eng/package-msix.ps1`.

Run `./eng/package-release.ps1 -Output artifacts/release -IncludeWindowsAppRuntime` from a Visual Studio Developer PowerShell to produce the portable ZIP. It contains `Unfurl.exe`, the Windows App SDK bootstrap DLL, the app-local Visual C++ runtime, libarchive codec dependencies, third-party notices, and Explorer integration scripts. `-IncludeWindowsAppRuntime` includes the signed x64 runtime MSIX payload (about 48 MiB); run `installer/install-runtime.ps1` after extracting it when that runtime is missing. The portable edition does not update automatically. The script fixes archive entry ordering and timestamps and prints a SHA-256 hash for the ZIP. The CI workflow builds the core and WinUI targets separately so a missing UI SDK cannot hide a core regression.

## Upstream study

The product and engineering constraints were derived from [L0stInFades/Unfold](https://github.com/L0stInFades/Unfold): task-oriented compression/extraction, native drag and drop, bounded preview, cancellation-aware streaming, no-overwrite atomic publishing, strict path validation, and no idle GPU work. Unfurl keeps those constraints and changes the shell, typography, material, title-bar behavior, and Explorer integration to Windows 11 conventions.
